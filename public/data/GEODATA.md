# Геоданные проектов (Лойиҳалар) — анализ, схема, визуализация

Источник: `projects.kml` (KML 2.2, EPSG:4326 / WGS84).
Пайплайн: `node scripts/kml-to-geojson.mjs` → `projects.geojson` + `validation-report.json`.

---

## 1. Структура исходных данных

| Параметр | Значение |
|---|---|
| Формат | KML → конвертирован в GeoJSON RFC 7946 |
| CRS | EPSG:4326 (lng, lat) |
| Регион | г. Ташкент (~69.17–69.47° E, 41.19–41.36° N) |
| Объектов в файле | **18** (`ID_00000`…`ID_00017`) |
| Геометрия | 17 × `Polygon`, 1 × `MultiPolygon` (MQ-0026, 2 контура) |
| Атрибуты (из HTML-таблицы в `<description>`) | `Tartib raqam`, `ID raqam (Qo'mita)`, `Yer maydoni`, `Maydon test` |

**Важно:** имя документа — «Лойиҳалар **31** та», но фактически в файле только **18** объектов. Поле `Tartib raqam` идёт с пропусками (1,2,4,5,6,8,12,16,19–28) — это подтверждает, что выгружено подмножество из ~31. → Запросить недостающие 13 объектов у источника.

## 2. Проверка и исправление геометрии (результат прогона)

| Проверка | Найдено | Действие |
|---|---|---|
| Незамкнутые контуры | **0** | — (все кольца замкнуты: первая = последняя точка) |
| Самопересечения | **0** | — |
| Дубликаты по ID | **0** | — (все `MQ-XXXX` уникальны) |
| Дубликаты по геометрии | **0** | — |
| Неверная ориентация | **0** | кольца уже CCW; скрипт всё равно форсит RFC 7946 (внешнее — CCW, дыры — CW) |
| Пересечения/наложения полигонов | **0** | — (объекты географически разнесены) |
| Расхождение атрибутов площади | **2** | помечены флагом `area_mismatch` |

**Расхождения площадей (`Yer maydoni` ≠ `Maydon test`):**
- `MQ-0048`: 9.9 vs 10 → вычисленная геодезическая площадь **10.0 га**
- `MQ-0016`: 100 vs 110.3 → вычисленная **110.37 га**

Вывод: вычисленная площадь совпадает с `Maydon test`, значит `Maydon test` — фактическая, а `Yer maydoni` — округлённое/проектное значение. В схеме сохранены оба + `area_computed_ha` (геодезический расчёт, сферическая модель R=6378137 м) как источник истины.

Совпадение `area_computed_ha` с заявленными значениями до 2 знаков по всем 18 объектам подтверждает корректность парсинга геометрии.

## 3. Структурирование по слоям и категориям

Сейчас все объекты — один класс «проект» (`type: "project"`), один слой `FeatureLayer0`. Рекомендуемая модель слоёв для веб-карты:

- **Слой `projects`** — все полигоны (основной).
- Группировка внутри слоя по **`status`** (когда появятся реальные статусы: `planned` / `active` / `done`) и по **диапазону площади** (см. §5).
- `MultiPolygon` (MQ-0026) рендерить как один объект с двумя частями — не разбивать.

## 4. Оптимальная схема атрибутов (реализована в `projects.geojson`)

```jsonc
{
  "id": "MQ-0044",            // string  — ID Qo'mita = бизнес-ключ
  "name": "MQ-0044",          // string  — подпись на карте
  "type": "project",          // enum    — класс объекта (для группировки/цвета)
  "status": "active",         // enum    — planned|active|done (сейчас дефолт)
  "order_no": 28,             // number  — Tartib raqam
  "area_declared_ha": 80.4,   // number  — Yer maydoni (проектная, га)
  "area_test_ha": 80.4,       // number  — Maydon test (фактическая, га)
  "area_computed_ha": 80.43,  // number  — геодезический расчёт из геометрии, га
  "area_mismatch": false,     // bool    — true, если declared≠test (>0.05 га)
  "created_at": null,         // string  — ISO-дата (нет в источнике → заполнить)
  "source_kml_id": "ID_00000" // string  — трассировка к исходному Placemark
}
```

Рекомендуется добавить при наличии данных: `district` (район), `responsible` (ответственный), `start_date`/`end_date`, `budget`.

## 5. Рекомендации по визуализации

### Цветовая схема
Объекты одного типа → кодировать **цветом по статусу**, **насыщенностью/штриховкой по площади**:

| Статус | Заливка | Обводка |
|---|---|---|
| planned (план) | `#FBBF24` @ 0.25 | `#B45309` |
| active (в работе) | `#3B82F6` @ 0.30 | `#1D4ED8` |
| done (завершён) | `#22C55E` @ 0.30 | `#15803D` |
| mismatch-флаг | — | пунктир `#EF4444` (подсветка спорных площадей) |

Пока единый статус — использовать один акцент (`#2957a5` brand-dark из темы проекта) с обводкой `#1D4ED8`, ховер — заливка +0.15 alpha.

### Группировка по типам
Легенда-переключатель: чекбоксы по `status`; отдельный тоггл «показать только `area_mismatch`». Категории площади (хороплет-стиль): `<25`, `25–75`, `75–150`, `>150` га.

### Подписи (labels)
- Показывать `name` (MQ-XXXX) в центроиде полигона при `zoom ≥ 13` (иначе перекрытие).
- При `zoom ≥ 15` добавлять `area_test_ha` второй строкой.
- Использовать collision-detection (MapLibre `text-allow-overlap:false`) чтобы избежать каши.

### Всплывающие карточки (popup)
Заголовок `name` + таблица: Tartib raqam, Статус, Площадь (test/declared/расчёт), флаг расхождения. Шаблон (Tailwind, по теме проекта):

```
┌─────────────────────────────┐
│ MQ-0044            [active]  │  ← name + статус-бейдж
├─────────────────────────────┤
│ № п/п:            28         │
│ Площадь (факт):   80.4 га    │
│ Площадь (расчёт): 80.43 га   │
│ ⚠ расхождение:    нет        │
└─────────────────────────────┘
```

### Фильтрация и поиск
- **Поиск** по `id`/`name` (MQ-номер) — автокомплит, при выборе `flyTo` + открыть popup.
- **Фильтры:** статус (мультиселект), диапазон площади (слайдер по `area_test_ha`), чекбокс «только спорные площади» (`area_mismatch`).
- Фильтрация — на уровне источника (MapLibre `setFilter` / Leaflet перерисовка слоя), без перезагрузки данных.

### Технические рекомендации рендеринга
- Размер `projects.geojson` мал (18 объектов) → грузить целиком, без тайлов.
- Библиотека: **MapLibre GL JS** (вектор, плавный зум, нативные `fill`/`line`/`symbol` слои и `setFilter`) либо **Leaflet** (проще). Под стек React 19 проекта — обёртка `react-map-gl` или `react-leaflet`.
- Авто-fit к bbox коллекции при загрузке.
- Подложка: спутник + улицы (район Ташкента), т.к. это границы реальных участков.
